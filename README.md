# 合唱プロンプター (Chorus Prompter)

Even Realities の **Even G2 スマートグラス** 用に作った、合唱の歌詞を表示するプロンプターアプリです。歌いながら **Even R1 リング**（またはグラス本体のタッチパッド）で歌詞を1節ずつ送ることができ、事前に同期しておけば **機内モード（Bluetooth はオン）でも動作**します。

## これは何か

[hub.evenrealities.com/docs](https://hub.evenrealities.com/docs) の "Even Hub" プラットフォーム向けに作られたアプリです。**iOS のネイティブアプリではありません**。実体は TypeScript/HTML の小さな Web アプリで、Even Realities 公式スマホアプリの中の WebView 上で動作し、公式 SDK (`@evenrealities/even_hub_sdk`) を通じてグラスに文字を表示したり、R1リング／タッチパッドの操作を受け取ったりします。Bluetooth 接続そのものは Even Realities 公式アプリが管理しており、このアプリのコードが直接 BLE を扱うことはありません。

公式テンプレート `text-heavy`（長文表示向けリーダー）をベースにしています。

## 特徴

- **歌詞は URL から取り込む**：曲ごとに Markdown ファイルの URL を登録すると、内容を取得してローカルに保存します。以降は Wi-Fi/モバイル通信がなくてもキャッシュから表示できます。
- **1つの URL で長大な曲を丸ごと扱える**：`## 2. Ave verum corpus` のような見出し2で楽章・曲を区切れます。マタイ受難曲やドイツ・レクイエムのような多楽章の大曲を1ファイルにまとめておけば、演奏中に電話へ戻らず通しで演奏できます（演奏会プログラム全体を1ファイルにする使い方にも対応）。
- **ページ番号・練習番号にも対応**：行頭の `<50>`（ページ番号）や `[A]`（練習番号）を認識し、グラス下部の情報表示行に反映します。
- **1クリック = 1段落分の前進**：空行区切りの「固まり」を単位に進みます。画面に収まらない固まりはクリックのたびに続きへスクロールし、収まりきったら次の固まりへ進みます。
- **操作は R1 リングでもグラス本体のタッチパッドでも同じ**：どちらで操作しても同じイベントとして扱われます。
- **バックグラウンドでも動作継続**：iOS では WebView がバックグラウンドでも動き続けるため、演奏中に画面をロックしても問題ありません。

## 画面構成・操作方法

### 電話画面（曲の管理・設定）

- 曲名と Markdown の URL を入力して「曲を追加 & 同期」
- 各曲の行には「再生」「同期」「削除」ボタン
- 「同期」を押すと最新の Markdown を取得し直します（オフライン時や URL が無効な場合は、前回同期したキャッシュはそのまま残ります）
- 曲一覧の下に**設定パネル**があり、以下を変更できます（すべて即座に反映され、次回起動時も保持されます）：
  - グラス表示の明るさ（0〜4）
  - 練習番号／曲名／ページ番号（情報表示行の各項目）の表示 ON/OFF
  - リングの UP/DOWN（上下スワイプ）で「練習番号ごと」「ページ番号ごと」「見出し2ごと」「見出し3ごと」のどの単位に移動するかの**既定値**（演奏中はグラス側のダブルタップでいつでも変更できます）

### グラス側（演奏中）

| 操作 | 動作 |
|---|---|
| クリック（タップ／下スワイプ） | 次のデータへ（固まりが画面に収まっていなければ続きへスクロール、収まっていれば次の固まりへ） |
| UP（上スワイプ） | 現在の移動単位で前の区切りへジャンプ |
| DOWN（下スワイプ） | 現在の移動単位で次の区切りへジャンプ |
| ダブルタップ | UP/DOWN の移動単位（練習番号／ページ番号／見出し2／見出し3）を選ぶ画面を開く。画面が出ている間は UP/DOWN で候補を選び、クリックで確定 |

画面下部の情報表示行には、左＝練習番号、中央＝曲名（複数楽章の曲では現在の楽章タイトルに自動で切り替わる）、右＝ページ番号を表示します（それぞれ電話側の設定でON/OFFでき、曲を通してずっと既定値のままの項目は自動的に非表示になります）。表示が切り替わったときは、その行全体が一度ゆっくり点滅します。

**グラス側に終了操作はありません**（ダブルタップは上記の移動単位選択に使われるため）。演奏を終えるときは、演奏中画面の「終了してライブラリに戻る」ボタンを押してください（グラス表示も同時に終了します）。

## 歌詞ファイル（Markdown）の書き方

```markdown
## 2. Ave verum corpus
[A]<1>Ave, ave verum corpus,
natum de maria, virgine vere

<2>[B]natum de maria, virgine vere
```

- **見出し2 (`## N. Title`)**：曲・楽章の区切り。番号（`N.`）は省略可能。1つのファイルに複数書けます（多楽章の大曲・演奏会プログラム向け）。見出し行自体は歌詞として表示されません。
- **見出し3 (`### Title`)**：曲中の任意の区切り（節・フレーズなど）。見出し2と違い専用の表示枠は無いため、`###` を取り除いた上で本文にそのまま表示されます。リングの移動単位を「見出し2ごと」「見出し3ごと」にすると、この区切りへジャンプできます。
- **ページ番号 `<N>`**：行頭に置くとそのページ番号が以降の行に持続します（次の `<N>` が出るまで）。ファイル冒頭で未指定の場合は `<0>` 扱いです。
- **練習番号 `[X]`**：行頭に置くとその練習番号が以降の行に持続します（`[A]` や `[1]`、`[003]` のような任意の文字列）。ページ番号と同じ行に順不同で併記できます。
- 空行で区切られた1ブロックが「固まり」（1回のクリックで進める表示単位）になります。見出し2をまたぐ固まりはできません。
- 見出し以外の Markdown 装飾（太字・斜体・` `` ` など）はグラスのフォントでは表現できないため、表示前に自動で取り除かれます。
- 英語・ドイツ語など単語区切りが明確な言語は単語境界で折り返し、日本語などは横幅いっぱいまで詰めて折り返します。
- ホスティング先は **CORS ヘッダを返す必要があります**。GitHub の raw コンテンツ（`raw.githubusercontent.com`）や Gist（`gist.githubusercontent.com`）はデフォルトで対応しているためおすすめです。それ以外のホスティングを使う場合は `app.json` の許可リストの変更も必要です（下記参照）。

## セットアップ

```bash
npm install
npm run dev
```

開発サーバーが `http://localhost:5173` で起動します。

### 動作確認方法

- **デスクトップシミュレータ**：
  ```bash
  npm run simulate
  ```
- **実機（G2 + R1）へ QR コードでサイドロード**（スマホと開発用 PC を同じ Wi-Fi に接続）：
  ```bash
  npx evenhub qr --url http://<開発PCのLAN IP>:5173
  ```
  表示された QR コードを Even Realities アプリの「開発者向け」→「QR スキャン」で読み込みます。

**補足（開発者向け）**：`evenhub-simulator` は `--automation-port <PORT>` オプションを付けると、ローカルに自動化用の HTTP サーバーが立ちます（公式ドキュメントには記載なし）。`GET /api/screenshot/glasses` でグラス表示の PNG スクリーンショットを、`POST /api/input`（body: `{"action":"click"|"double_click"|"up"|"down"}`）で R1/タッチパッド操作をシミュレートできます。手動でウィンドウを操作しなくても動作確認ができるため、詳細は `CLAUDE.md` を参照してください。

### プライベートビルドとして配布・再登録する

開発用QRサイドロードは開発機と同じWi-Fiにいる間しか使えません。外出先でも使うには、端末にインストールする「プライベートビルド」にします。

**初回のみ**：Even Hub のアカウントは **Even Realities 公式スマホアプリの中で作成**します（Webポータル単体にサインアップ機能はありません）。作成したアカウントで https://hub.evenrealities.com/login にもサインインできます。

**バージョンを上げるたびに繰り返す手順**：

1. `app.json` の `"version"` をセマンティックバージョニングで上げる（Even Hub は同一バージョンの再アップロードを想定していません）
2. ```bash
   npm run release
   ```
   `scripts/release.sh` が `npm run build` → バージョン付きの `.ehpk`（`releases/chorus-prompter-vX.Y.Z.ehpk`）の作成までを行います。バージョンを上げ忘れて同名ファイルが既にある場合はエラーで止まります。
3. https://hub.evenrealities.com/login でサインインし、このアプリのプロジェクトを開いて **「Private builds」タブ**から `.ehpk` をアップロード
4. スマホの Even Realities アプリ → **「Even Hub」タブ（Developer Mode）→ Me → Apps → Private builds** から該当バージョンを探して **Install**

手順3・4はWeb/スマホでの手動操作で、CLIから自動化はできません（`evenhub-cli` にアップロード・公開に相当するコマンドは無いことを確認済みです）。詳細な背景・確認済みの制約は `CLAUDE.md` の「Even Hub プライベートビルド登録手順」を参照してください。

## ディレクトリ構成

```
chorus-assistant/
├── app.json              # マニフェスト（パッケージID、権限、ネットワーク許可リストなど）
├── index.html             # WebView のホストページ
└── src/
    ├── main.ts              # エントリポイント。曲ライブラリと画面遷移をつなぐ
    ├── ui.ts                  # 電話画面のUI（曲一覧・追加フォーム・演奏中画面）
    ├── library.ts              # 曲データの CRUD（localStorage 永続化）
    ├── settings.ts              # 明るさ・表示ON/OFF・UP/DOWNモードなどの設定（localStorage 永続化）
    ├── sync.ts                  # URL から Markdown を取得してキャッシュを更新
    ├── lyrics.ts                 # Markdown → 楽章・ページ番号・練習番号・折返し済み行に変換するパーサー
    ├── performer.ts               # グラス側の描画・R1/タッチパッド操作・情報表示行の処理
    └── layout.ts                   # グラスの表示領域（576×288px）の共通定数
```

## `app.json` の主な設定項目

```json
{
  "package_id": "com.igarashi.chorusprompter",
  "name": "合唱プロンプター",
  "permissions": [
    {
      "name": "network",
      "desc": "Markdown の歌詞ファイルを指定 URL から取得し、オフライン再生用にキャッシュするため",
      "whitelist": [
        "https://raw.githubusercontent.com",
        "https://gist.githubusercontent.com"
      ]
    }
  ],
  "supported_languages": ["ja"]
}
```

**歌詞を GitHub 以外の場所（自前サーバーや別のクラウドストレージなど）でホストする場合は、`whitelist` にそのドメインを追加してから同期してください。** 登録されていないドメインへの `fetch()` はアプリ側で事前にブロックされます（加えてホスティング側の CORS 設定も必要です）。

## 既知の制限事項・今後の課題

- **アプリアイコンが未設定**です（`public/icon.png` が存在しません）。配布パッケージを作る前に用意してください。
- **曲の選択は電話画面のみ**で行います。グラス側のリスト表示で曲を切り替える機能（SDK 0.0.14 で使えるリスト／メニューコンテナを利用）は未実装で、将来の拡張候補です（同一ファイル内の楽章切り替えは演奏中に自動で行われるため対象外）。
- 情報表示行は3項目（練習番号・曲名・ページ番号）を**1つのテキストコンテナ**にまとめて描画しています。そのため「変わった項目だけ点滅」ではなく、**行全体が点滅**します（詳細な理由は `CLAUDE.md` を参照）。

### 動作確認の状況

デスクトップシミュレータの自動化 API（スクリーンショット・入力送信）を使い、`src/test-harness.ts` で `parseSong`/`startPerformance` を直接叩く形で、以下は実際に動作を確認済みです：

- 見出し2による楽章区切りと、フッター中央の曲名が楽章に応じて自動切り替わること
- 見出し3 (`###`) が本文表示を保ったまま移動単位の区切りとして機能すること
- ページ番号 `<N>` ／練習番号 `[X]` の行頭マーカー解析（順不同・混在含む）と持続、範囲表示（`"2-3"` / `"A-B"`）
- 曲を通して既定値のままの項目（ページ番号・練習番号）が自動的に非表示になること
- 画面に収まらない固まりのクリックによるスクロール送り（1行オーバーラップで進み、末尾はオーバーラップを広げてクランプ）
- UP/DOWN（練習番号／見出し2／見出し3モード）での前後の区切りへのジャンプ、曲頭・曲末でのクランプ
- ダブルタップで開く移動単位の選択画面（現在値へのカーソル表示、UP/DOWNでの候補選択とクランプ、クリックでの確定、選択中の再ダブルタップの無視）
- 情報表示行が変化した際の点滅トリガー
- 「終了してライブラリに戻る」に相当する処理が `shutDownPageContainer(1)` を呼んでグラス側コンテナを実際に閉じ、正しい再開位置を保存すること
- 電話画面側 UI の見た目（曲一覧の空状態・同期済み/エラー状態の行、設定パネル、演奏中画面のヘルプ文言とボタン）— `/api/screenshot/webview` で確認
- `tsc --noEmit` / `vite build`

一方、以下は **未検証** です。本番の演奏で使う前に確認してください：

- **UP/DOWN の「ページ番号ごと」モード**：「練習番号ごと」モードと対称な実装のため、シミュレータでの個別実行はしていません
- **実機（G2 本体・R1 リング）** 固有の挙動：実際の Bluetooth 遅延、タッチパッドの感度、輝度設定の見え方、機内モードでの安定動作など
- **電話画面側 UI の操作感**（フォーム入力やボタンタップの実際のタッチ操作）：自動化 API が webview 内の操作には対応していないため未確認

なお、電話画面側 UI の**見た目**（曲一覧の空状態・同期済み/エラー状態、設定パネル、演奏中画面）はスクリーンショット API（`/api/screenshot/webview`）で確認済みです。

上記の未検証項目を含め、**本番で使う前に必ず実機で一通り操作を確認してください。**
